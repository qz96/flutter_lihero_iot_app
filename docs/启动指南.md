## 三、日常启动（推荐流程）

### 步骤 1：启动模拟器

```powershell
flutter emulators --launch lihero_pixel
```

或用 SDK 自带命令：

```powershell
& "D:\rtu_build_tools\android-sdk\emulator\emulator.exe" -avd lihero_pixel
```

等待模拟器桌面出现（首次冷启动约 30–60 秒）。

查看可用设备：

```powershell
flutter devices
# 期望看到：emulator-5554 • sdk gphone64 x86 64 • android-x64 • Android 15 (API 35)
```

若模拟器列表为空：

```powershell
flutter emulators          # 查看已存在的 AVD
adb devices                # 查看已连接的设备
```

### 步骤 2：运行 App（调试模式，支持热重载）

```powershell
cd d:\work\project\flutter_lihero_iot_app
flutter run --dart-define-from-file configs.json
```

> **必须**带上 `--dart-define-from-file configs.json`，否则 App 读不到服务端地址和密钥。

多设备时指定目标：

```powershell
flutter run -d emulator-5554 --dart-define-from-file configs.json
```

### 步骤 3：改 UI 样式与热重载

调 UI 时**不需要重启 App**。`flutter run` 运行期间，改完代码保存（Ctrl+S），然后按 `r` 即可。

| 按键 | 作用 | 速度 | 适用场景 |
| --- | --- | --- | --- |
| `r` | 热重载 Hot Reload | ~1 秒 | 改颜色/间距/圆角/字体/布局/文案。**保留登录状态和当前页面** |
| `R` | 热重启 Hot Restart | ~3-5 秒 | 改了 `initState`、全局变量、Provider/Bloc 初始化逻辑 |
| `p` | 显示布局网格 | — | 对齐检查 |
| `h` | 显示全部可用按键 | — | 查看调试开关 |
| `q` | 退出运行（App 关闭） | — | 结束调试 |

#### 推荐：开启自动热重载

加 `--hot` 参数后，**保存文件即自动重载**，连按键都省了：

```powershell
flutter run --dart-define-from-file configs.json --hot
```

或直接使用 `run.ps1`（已默认开启自动热重载）：

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

如需改回手动模式：

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 -NoHot
```

> **重要前提**：热重载只在 `flutter run`（调试模式）下有效。
> 如果是 `flutter build apk` 构建后安装的 Release 包，或从桌面图标打开的 App，改代码**必须重新构建安装**。

#### 热重载的限制

以下几种情况按 `r` 不生效，需按 `R`（热重启）或重新 `flutter run`：

- **`main()` 函数内的改动**：本项目 `lib/main.dart` 里做了 `Hive.initFlutter()`、`setUpRootDependencies()`、Firebase 初始化、`FlutterNativeSplash` 等一次性初始化，改这些必须热重启。
- **修改静态字段的初始值、枚举、类型定义**。
- **修改原生代码**（`android/` 下的 Kotlin、`AndroidManifest.xml`、Gradle 配置）—— 需完全重新运行。
- **新增/删除依赖**（改 `pubspec.yaml` 后要重新 `flutter run`）。

调 UI 样式通常只改 `lib/` 下的 Widget 文件，属于热重载最擅长的场景。

#### 如何确认生效

按 `r` 后终端会输出：

- `Reloaded X of Y libraries in 800ms` → 已生效。
- `Not all changed program elements ran during the reload` → 部分改动需按 `R`。

## 六、常见问题

### 1. 新终端里 `flutter` 不是内部或外部命令

环境变量是用户级，需**新开终端**，或重启编辑器（让进程重新加载环境变量）。临时方案：

```powershell
$env:Path = "D:\rtu_build_tools\flutter\bin;" + $env:Path
```

### 2. `flutter doctor` 报 Android licenses 未接受

```powershell
flutter doctor --android-licenses
```

一路输入 `y` 接受。

### 3. 构建报 `Unsupported class file major version` / Gradle 与 JDK 不兼容

项目要求 JDK 17。确认 `JAVA_HOME` 指向 JDK 17：

```powershell
echo $env:JAVA_HOME     # 应为 D:\work\tool\jdk\jdk-17.0.15+6
java -version           # 应为 17.x
```

### 4. 模拟器启动卡在开机画面

先确认硬件加速可用（Intel HAXM / Hyper-V / WHPX）：

```powershell
& "D:\rtu_build_tools\android-sdk\emulator\emulator.exe" -accel-check
```

若加速不可用，需在 BIOS 开启虚拟化（VT-x / AMD-V），或在「Windows 功能」中启用 `Hyper-V` / `Windows 虚拟机监控程序平台`。

### 5. App 启动后连不上服务端

- 确认 `configs.json` 中 `thingsboardApiEndpoint` 正确且**模拟器能访问该地址**。
- 模拟器访问宿主机用 `10.0.2.2`；访问局域网地址需宿主机防火墙放行。
- 若服务端是 `http`（非 https），确认 Android 端已允许明文流量（项目 `AndroidManifest` 已有配置，一般无需改动）。

### 6. 想装到真机上调试

1. 手机开启「开发者选项 → USB 调试」。
2. USB 连接电脑，手机上允许调试授权。
3. `flutter devices` 确认设备出现。
4. `flutter run -d <设备ID> --dart-define-from-file configs.json`。

## 七、一键启动脚本

项目根目录已内置 `run.ps1`，自动完成：环境检查 → 配置文件检查 → 同步依赖 → 启动模拟器 → 运行 App。

### 用法

```powershell
cd d:\work\project\flutter_lihero_iot_app
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

指定其他模拟器：

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 -Avd <AVD名称>
```

### 脚本行为

| 步骤 | 说明 |
| --- | --- |
| [0/4] | 检查 `flutter` / `adb` 是否可用，打印路径与 `JAVA_HOME` |
| [1/4] | 检查 `configs.json`；不存在则从模板生成并退出；检测到密钥仍是占位符时提示确认 |
| [2/4] | 执行 `flutter pub get` 同步依赖 |
| [3/4] | 若已有模拟器在线则跳过；否则启动 AVD 并轮询 `sys.boot_completed` 直到就绪 |
| [4/4] | `flutter run --dart-define-from-file configs.json`（前台运行，支持热重载） |

> 提示：脚本以 UTF-8 BOM 保存。若手动编辑后出现中文乱码或「字符串缺少终止符」报错，
> 请用「另存为 → 编码：UTF-8 带 BOM」保存（Windows PowerShell 5.1 默认按 GBK 解析 `.ps1`）。
